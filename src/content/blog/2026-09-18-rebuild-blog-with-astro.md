这个站是第二次重建了。上一次是 Hexo + Fluid，写得不多，但每次打开都觉得慢——不是网络慢，是首页要先加载一串用不太上的 JS 才把标题显示出来。

这次换到 Astro，理由很简单：**默认输出纯 HTML，不给我塞多余的 JS。**

## 换之前我先想清楚的三件事

换技术栈很容易变成"折腾本身"，所以我先逼自己回答三个问题：

1. **是不是写作频率低到不值得换？** 不是。备考笔记、毕设实验记录，后面一定会有大量零碎内容要往外倒。
2. **旧站最难受的是什么？** 首屏有闪烁、代码块样式难看、移动端阅读体验差。
3. **换完能不能更省事？** 能。Astro 的 Markdown 直出 + 内置代码高亮，少装一堆插件。

## Hexo 和 Astro 的实际差异

| 维度 | Hexo | Astro |
| --- | --- | --- |
| 生成物 | HTML + 主题携带的 JS | 默认纯 HTML，按需加载 |
| 内容位置 | `source/_posts/` | `src/content/blog/` |
| 代码高亮 | 需要插件（prism / highlight） | 内置 Shiki，无需配置 |
| 构建速度 | 文章过百后明显变慢 | 明显更快 |
| 面向 | 博客 | 博客 + 文档 + 作品集 |

一句话总结：Hexo 是"博客专用工具"，Astro 是"静态站框架"。前者开箱即用，后者上限更高。

## 现在这个站长什么样

- **内容**：Markdown 写在 `src/content/blog/`，文件名即 URL。
- **样式**：手写 CSS，没有 UI 框架。主色只有一个，其余走灰阶。
- **部署**：推到 GitHub，Actions 自动构建并发到 Pages。
- **性能**：没有 CSS 框架、没有运行时 JS，唯一的脚本是暗色模式切换。

## 迁移时的几个坑

**Frontmatter 字段要对齐。** Hexo 用 `date` + `categories` + `tags`，Astro 这边我把 schema 定成 `pubDate` + `tags`，`categories` 直接扔掉——分类和标签同时存在，最后一定会乱。

**图片路径。** Hexo 的 `asset_folder` 习惯不能直接搬，Astro 里统一放 `public/` 或跟文章同目录用相对路径。

**别一次迁完。** 我保留了旧站，新站先跑起来，文章慢慢搬。
